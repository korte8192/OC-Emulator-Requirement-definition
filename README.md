# OC-Emulater要求定義書
ユーザーが作成したオリジナルキャラクター（立ち絵、性格、対話者との関係性など）の設定を登録し、LLM（Groq API）を活用してキャラクターになりきらせた対話・セリフ提案を行うアプリです。将来的にノベルゲーム等の外部システム連携を想定した設計を目指しています。
## システム概要 ##

### アプリ名:OC-Emullater

### 目的：
- ユーザー独自のキャラクタープロファイルに基づいたAIロールプレイ対話
- 創作活動におけるセリフ検討・アイデア出しのサポート
- 外部ノベルゲームエンジンへのリアルタイム会話エンジン共有

### 使用LLM

Groq API

## 機能要件

### 立ち絵の登録,管理

- 画像の読み込み・割り当て

- 対話背景、会話生成に利用

- このモデル内での学習の完結、生成AIにイラストを読ませるのが嫌な人のためにアプリ内で学習をとどめ、オリジナルのイラストのデータ蓄積をさせない。

### プロファイル詳細設定

- 基本情報：キャラ名、一人称、二人称、口調、語尾

- 性格、客観的評価、長所、短所、行動原理

- 他キャラ、対話者との関係性、距離感、エピソード

- セリフ例

- パラメータをTRPGのキャラシ風に入力

### プロファイルの保存

-　キャラクタープロファイルの作成・編集・複製・削除

- JSON形式でのインポート / エクスポート機能

## 非機能要求定義

- cost:開発・個人利用フェーズにおいて、Groqの無料枠（Free Tier）の範囲内で運用可能とすること

- security:APIキーは端末ローカルに安全に保存し、外部サービスへの不必要な送信を行わない

## 開発ロードマップ

### 1.プロンプト設計、API動作検証

キャラクター設定をプロンプト化し、Groq APIで期待通りのロールプレイができるかテスト

### 2.Androidアプリ基盤構築

設定入力画面およびローカルDBへの保存処理の実装

### 3.Groq API通信部 & チャットUIの実装

リアルタイムチャット画面の構築

## 実装メソッド

- /chat:json形式でマスターデータ、会話履歴データ、ユーザーのメッセージをサーバーにkotlinから送信することでそれらを引数にgroqと通信し返答を作ってくれる。

- /generate-masterdata:最初に実行するものユーザーの入力した情報からAIが補完し情報を作ってくれる補完すべきものには【要AI補完】したものには【補完済み】を常に入れるようにしてる

- /OCbrain:十往復ごとにkotlinにより呼び出される、ノートを作り出すこと、そのノートをuserid.jsonのオブジェクトとして追加していくこと。
そしてそれらのオブジェクトが11個を超えたとき１つのノートとしてそれら11のオブジェクトをまとめて要約させる。

- /OC-Omoidasi:固有名詞が出てきたときに要約を探索してもらうが、なかった場合にAIが呼び出すようのもの。履歴からそれら固有名詞をpythonサーバーを使って探す
